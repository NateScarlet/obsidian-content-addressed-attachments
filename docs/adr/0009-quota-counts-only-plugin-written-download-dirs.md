# 下载配额只统计插件会写入的下载目录

「下载目录」在配置上不止一个：全局 `downloadDir`，加上每个网关各自声明的 `downloadDir`。
其中 URL 模板为空的网关语义是「仅从下载目录读取已有文件」（`gatewayProducesSource`），它的
目录可能由外部应用管理——最典型的是用户把 IPFS 应用自己的存储目录填进来，插件只从那里读
文件，不往里写。

配额与自动清理若把这些目录一并计入，会造成真实的数据损失：自动清理直接按 CAS 命名约定删除
磁盘文件、不查元数据（见
[ADR-0006](./0006-cleanup-walks-download-dir-instead-of-metadata.md)），一个外部应用管理的
目录进了清理目标，就是替对方删文件。

因此配额的目录口径窄于「全部下载目录」：只统计插件会往里写的目录——全局 `downloadDir`，加上
URL 模板非空（因而会产生远程来源）的网关所声明的目录。判据按**目录集合**而非配置来源：同一
目录只要还被任一会产生来源的配置使用，就仍参与配额；只有当它仅被「仅用于读取」的配置使用时
才被排除。

**Considered Options**:

- 把全部下载目录计入配额、清理前查元数据确认归属：归属是配置语义（「这个目录归谁管」），
  不存在于磁盘上，查元数据解决不了；而自动清理已刻意不查元数据，否决。
- 只让全局 `downloadDir` 参与配额：判据过窄，用户为不同网关设的下载目录同样会持续侵占磁盘
  却不受任何约束，否决。
- 用「目录是否曾被插件写入过」判定：写入历史在元数据里，而元数据正是可丢弃的索引，索引清空
  后口径会漂移，否决。

**Consequences**:

- 排除只作用于配额检查的目录集合；读取、恢复与文件管理器「下载」标签页仍使用完整的下载
  目录列表（`getDownloadDirs` 不区分口径）。
- 手动清理不受影响：仅用于读取的目录仍在「下载」标签页出现、仍可手动清理——手动清理是用户
  显式指定目录，插件不替他判断归属。
- 配额检查对写入目标目录短路：本次写入落在不参与配额的目录上时不触发清理、也不计入占用。
- 缺口的口径是「超出配额 + 本次写入的体积」，保证新副本落盘后仍在配额内；无可删副本时放弃
  清理、照常写入，由插件合并提示一次。
- 新增网关配置或新增一类「不落盘的目录」语义时，必须同步复核配额判据，否则新类别会自动
  落进清理目标。
