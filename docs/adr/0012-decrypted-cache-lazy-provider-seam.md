# 解密缓存作为独立 module，通过 lazy provider 获取明文

解密缓存的存取与清理从 URL 解析编排中剥离为独立 module（置于本地文件存储层），seam 位于「需要缓存的明文」与「缓存存储」之间：调用方传入内容 CID 与一个 lazy 的明文提供者 `() => Promise<DecryptedResult | undefined>`，module 先按 CID 查内存 blob 与磁盘缓存，命中即返回且不调用提供者；未命中才解密，并按 `maxBlob` 决定内存 blob 还是落盘。缓存键统一为 CID（而非原加密文件路径），防抖定时器与 `Symbol.dispose` 生命周期由 module 自持，上层仅转调释放。

**取舍**：急切传入明文的接口更简单，但会在缓存命中时仍执行解密——当用户密钥被清除而缓存文件尚在时，本可正常显示的附件会因缺密钥抛错。lazy provider 保留了「命中即不解密」的既有行为，代价是 module 接口多一层间接。缓存键从路径改为 CID 使内容寻址语义一致，同一 CID 的多路径引用只保留一份缓存。module 不接触展示与错误语义：缓存目录未配置时抛语义化错误，由调用方转成占位符或用户可见错误。
