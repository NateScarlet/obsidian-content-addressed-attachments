# 被禁用的网关等同于不存在

网关配置带 `enabled` 开关，但原先它只在一处生效：构建远程来源时跳过禁用的网关，于是
「禁用」只意味着不从这里下载。它声明的 `downloadDir` 仍被两个下载目录口径收集——全部
下载目录（CAS 读取白名单、恢复落盘范围、文件管理器「下载」标签页）与参与配额的目录
——于是被禁用的网关仍在被读取、仍会被清理，占用照旧计入配额。用户的本意是「先别用它」，
得到的却是「只不下载」。

因此我们决定：**禁用是配置状态，不是在声明副本位置。** 被禁用的网关不声明副本位置，
其目录不进入任何下载目录口径：不在读取范围、不出现在「下载」标签页、不被手动清理、
不计入占用也不被自动清理。重新启用即重新进入各口径，无需任何磁盘操作。

这与 [ADR-0009](./0009-quota-counts-only-plugin-written-download-dirs.md) 互补而非
替代：两者共用同一批目录配置，判据与作用范围都不同。ADR-0009 按「这个目录归谁管」
排除（URL 模板为空的网关目录可能由外部应用管理），只收窄配额口径；本 ADR 按「这个配置
现在生效吗」排除，连读取与手动清理一并收窄。

**Considered Options**:

- 停用只影响下载，目录仍留在读取范围与配额内：结果更糟——自动清理照旧遍历并删除该目录
  里超保留期的副本，用户刚「停用」的目录反而被清空，否决。
- 停用时把目录里的副本迁走或删除：停用是设置开关，不应有磁盘副作用；副本删除是清理
  与保留期语义的事（见
  [ADR-0005](./0005-download-cleanup-overrides-locked-copies.md)），否决。
- 停用只收窄读取范围、配额仍计入：清理目标仍包含用户以为已经撒手的目录，与 ADR-0009
  排除仅读取目录的同一条理由（清理直接删磁盘文件、不查归属），否决。

**Consequences**:

- 启用/停用只改变集合，不触发任何磁盘操作：该目录里已有的副本原样留在磁盘上，只是不再
  被插件读取、清理或统计。
- 文件管理器的文件列表按元数据列出、与目录无关，因此这些附件仍会显示在列表里，直到
  全量重建索引按目录白名单重新扫描（见
  [ADR-0002](./0002-rebuild-index-streams-by-probing-remaining-dirs.md)）后其记录才消失；
  重新启用网关后再重建一次即可恢复。在此之前，消失的只是「下载」标签页里的该目录本身。
- 判据按目录集合而非配置来源：与全局 `downloadDir` 或其它启用网关重名的目录照常参与
  全部口径，不会因为它同时被某个禁用网关声明而被排除。
- 下载目录有两层判据（配置生效、会产生远程来源），两者作用于不同口径：新增网关类别或
  新的「不落盘」语义时，两个口径的判据都必须一并复核。
